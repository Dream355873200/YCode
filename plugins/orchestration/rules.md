# 多 Agent 编排规范

本插件提供三种编排工具。先判断任务形态再选择，能直接做的小任务不要编排。

## 三种工具

### create_pipeline —— 一次性数据流 DAG
- 适合：任务能拆成**依赖关系固有**的多个阶段（如 提取→翻译→审核），上游产出就是下游输入
- 用 spec 声明节点（instruction / tools / depends_on / injects / output），提交后引擎构建校验并执行
- 有 `injects` 下游的节点自动获得 push_task 工具，把产出按声明的 output 格式逐条推进下游队列；节点间交付默认 Markdown 片段
- 节点执行时右栏 Pipeline 面板实时显示 DAG 状态图
- 不适合：依赖关系要你自己现场猜的任务——直接自己做，或派子代理

### run_team —— 单次任务的多角色协作
- 适合：一个任务需要多种职责协作（如 调研+分析+写作），你提交团队编制（leader 指令 + 成员角色与工具）和总任务
- leader 拆解分派、成员并行执行（过程实时可见）后汇报，leader 汇总返回
- 成员的 tools 只能从当前会话可见工具里选

### team_dispatch —— 向常驻团队分派（Teams）
- 团队由**用户**在团队面板创建（队长 + 成员，成员是持久会话、跨任务有记忆）；你只是指挥方
- `team_status` 看成员忙闲与当前活动；`team_dispatch` 分派子任务（成员忙则自动排队，可在同一轮并行分派多个）；`team_read` 读成员产出与历史摘要
- 成员的产出会作为工具结果回传给你，同时进入团队群聊；用户在群聊里可以随时插话

## 选择判据

1. 阶段间是固定格式的数据流水线（上游产出=下游输入）→ **create_pipeline**
2. 多个角色围绕同一个任务协作、需要汇总 → **run_team**
3. 目标属于用户已创建的团队 → **team_dispatch**
4. 任务不大、你自己两三轮能做完 → 不编排，直接做
