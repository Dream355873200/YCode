# YCode 2.0 设计：对话为中心的多智能体工作台

> 2026-10-24。起因：插件 / 模式 / 团队「有点混乱」。本文对标 Codex 一类 agent 应用，
> 定下用户心智、界面骨架与引擎架构，并给出迁移方式。原则不变：关系靠操作体现，
> 不靠界面上的说明文字。

## 一、混乱的根因（审计结论）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 「模式」一词两义 | 标题栏的模式 = 能力组合（mode.json）；输入框的模式 = 权限档位。且权限档位是**引擎全局**的，在 A 项目切了 B 项目也变 |
| 2 | 插件装了却用不上 | 插件只有被某个模式引用才对会话可见（游戏插件曾因此对所有会话隐形）；设置页把内部分层（模式/插件/提示词/工具集/子代理/MCP/技能）平铺成 7 个一级分区 |
| 3 | 一个项目只有一段对话 | 会话 ID 由项目目录派生，没有「新对话」，长任务只能挤在一条时间线里，无法并行 |
| 4 | 协作能力各自为政 | 团队、流水线是右栏两个孤立 tab；成员能力用「按工具集 / 继承模式」描述，是零件语言 |
| 5 | 团队会话串台（潜在 bug） | 团队会话 ID = `team-<名>-<成员>`，不含项目——两个项目里同名团队共用会话与角色卡 |
| 6 | 文案与形态停留在 Flutter 时代 | 空态写「AI 自动开发、自动上真机测试」，快捷按钮是 emoji |

## 二、用户心智：三层组合 + 一条任务线

```
插件 Plugin     能力包：工具、技能、子代理、MCP、右栏面板          设置 > 插件（启停）
   │ 组合
智能体 Agent    指令 + 一组插件 = 一种「工作者」                    设置 > 智能体；输入框随时切换
   │ 投入
对话 Thread     在某个项目里与一个智能体协作的一条任务线             侧栏：项目 → 对话（可并行）
团队 Team       多个智能体各带身份、常驻协作的群聊对话               侧栏：项目 → 团队
```

- **智能体**取代「模式」（引擎内部仍叫 mode，清单仍是 mode.json，避免资产迁移）。
  团队成员 = 智能体 + 一段身份描述——「角色卡和模式重合」的问题在名词层面消失。
- **权限**取代输入框里的「模式」，且是**对话级**的（持久化在对话绑定里）：
  规划（只读）/ 逐项审批 / 自动编辑 / 完全放行。
- **流水线**不是独立名词：它是对话里智能体发起的一次执行，以工具卡 + 右栏运行视图呈现。
- 子代理保留原名：智能体执行中委派出去的助手。

## 三、界面骨架

```
+ 侧栏 --------------+ 顶栏：项目 / 对话标题（可改名）          [变更 +12 -3] [右栏] +
| [Y]                |                                                             |
| [+] 新对话  Ctrl+N |   空对话：智能体图标 + 名称 + 一句话描述                      |
| [Q] 搜索    Ctrl+K |           大输入框 + 智能体声明的「开场建议」                  |
|                    |   有内容：时间线（工作过程折叠 / 正文 / 交互卡）              |
| 项目           [+] |                                                             |
| v test2     [+][..]|                                                             |
|   (转) 重构数据层  | +- 输入框 ------------------------------------------------+ |
|   (!)  等你确认    | | [智能体: 代码 v] [权限: 自动编辑 v]  (环) [模型 / 思考 v] | |
|   ( )  修复崩溃 2h | +---------------------------------------------------------+ |
|   [团] qa-team     +- 右栏 tab：变更 / 浏览器 / 文件 / 任务 / 计划 / 流水线 / 插件面板
| > TODO             |                                                             |
| (点) 模型名 [设置] |                                                             |
+--------------------+-------------------------------------------------------------+
```

图中括号标记只示意状态位置，实际一律用 lucide 图标。

- **侧栏**：项目分组，组内列对话（状态：运行中 / 等你处理 / 失败 / 未读）与团队；
  悬停出「在此项目新建对话」与「…」菜单（重命名 / 归档 / 删除），右键同一套菜单。
- **新对话是草稿**：点「新对话」只出空态，发出第一条消息时才在引擎创建对话（不留空壳）。
- **团队是一种对话**：在侧栏与普通对话并列，打开后群聊占据主区，成员时间线在右栏。
  成员忙时收到的插话收成一行（点开看全文），与群聊里的原发言重复时不再单列。
- **变更审查**取代 Git 面板：文件级 +/−、逐文件 diff、撤销单文件、提交（可让 AI 写提交说明）、
  分支切换与推送。
- **命令面板 Ctrl+K**：跨项目搜对话 / 项目 / 文件，执行常用操作（`>` 操作、`#` 对话、`@` 文件）。
- **设置**：通用（常规 / 模型）· 能力（智能体 / 插件 / 技能）· 进阶（提示词 / 工具集 / 子代理 / MCP）。
  智能体页与插件页**双向开关**：在插件页就能把它加进某个智能体，内置智能体被改时
  自动生成同 id 的用户覆盖（可一键恢复默认）。

### 3.1 对话状态胶囊（YCode 特有的组合）

对话区右上角悬浮一枚胶囊：**智能体头像 + 一条主状态 + 活动计数**（子代理 / 后台终端）。
主状态按优先级取一条：流水线进度 > 正在做的任务 > 进行中的目标 > 本轮改动 +/− >
已达成的目标 > 刚完成的任务 > 计划标题。展开为面板，分区为目标（轮次、验收结论、
暂停 / 继续）、进程（任务清单）、协作（子代理与流水线）、终端（后台任务）、计划、
工作区（当前智能体的插件此刻持有的资源：内置浏览器页面、已连接的真机、MCP 健康度）。
展开偏好三档：自动（容器 ≥ 1120px 时展开、时间线让位，窄时收成胶囊）/ 始终展开 / 始终收起。

### 3.2 目标（持续推进直到验收通过）

输入框的「目标」开关把这条消息设为对话目标。每轮运行结束后引擎用一次模型调用验收
（失败时放行，不卡住用户）；未通过就以「继续推进目标（第 N 轮）」作为下一条消息继续，
时间线上画成轮次分隔而非用户气泡。用户叫停 / 运行出错 → 目标暂停，不擅自继续；
引擎重启时把进行中的目标一律暂停。续跑由当前窗口驱动，所以每一轮都和普通轮一样实时可见。

### 3.3 运行到手机（Flutter 智能体的闭环）

右栏「手机」面板对 Flutter 项目多一行「应用」：运行（构建 → 安装 → 启动，并自动开投屏）、
热重载、热重启、停止，日志尾随手可看。对话一轮改完 Dart 文件后，若应用正在运行，
自动热重载并在时间线记一笔（可在面板关掉）。智能体写代码、你在旁边的真机上立刻看到效果。

## 四、引擎架构

### 4.1 对话注册表（threads.go）

引擎成为对话元数据的**唯一写入方**（桌面壳不再直接写 session-map.json）：

```jsonc
// ~/.amobilecreater/session-map.json（向后兼容：旧条目只有 dir/mode）
{ "<id>": { "dir": "…", "mode": "code", "title": "重构数据层", "titleSource": "ai",
            "createdAt": 1761300000000, "permission": "accept_edits", "archived": false } }
```

| 端点 | 作用 |
|---|---|
| `GET /threads?dir=` | 对话列表：绑定 + 会话摘要（状态、更新时间）+ 未决交互（ask / approval） |
| `POST /threads` | 创建对话（dir / mode / permission / 首条消息 → 临时标题） |
| `POST /threads/{id}` | 局部更新：标题、智能体、权限、归档（权限即时作用于进行中的运行） |
| `DELETE /threads/{id}` | 停止运行 → 删除会话历史 / 任务文件 / 子代理轨迹 / 绑定 |
| `POST /assist/commit-message` | 由 diff 生成提交说明（一次性模型调用） |

- **自动标题**：首条消息先给临时标题；首轮运行结束（Observer.OnSessionEnd）后用模型
  生成短标题。用户手动改过的标题永不覆盖。
- **对话级权限**：`WithSessionPermissionMode` 钩子按「团队 → 对话绑定」解析；
  更新权限后对该会话 `ClearSessionPermissionMode` 让钩子立即重算到进行中的审批门。
- 旧数据零迁移：既有 `amc-<目录名>-<哈希>` 绑定就是每个项目的第一段对话；`-git`
  辅助会话不再列出。

### 4.2 团队

- 会话 ID 改为项目隔离：`team.json` 新增 `sessionPrefix`（`team-<目录哈希>-<名>`，
  创建时写入）；旧团队无此字段时沿用 `team-<名>`，历史不丢。
- 队长新增 `agent`（能力基底智能体），与成员的 `mode` 同义；队长的 `mode` 仍是审批策略。

### 4.3 智能体清单增量

`mode.json` 新增可选字段：`icon`（图标键，桌面壳映射到 lucide）与
`starters`（开场建议 `[{label, prompt}]`，≤ 6 条）。新增内置智能体「办公文档」。

### 4.4 对话目标（goals.go）

目标存在对话绑定里（`goal: { objective, status, iteration, maxIterations, … }`）。

| 端点 | 作用 |
|---|---|
| `POST /threads/{id}/goal` | 设定目标（`{objective}`） |
| `POST /threads/{id}/goal/verify` | 验收本轮：返回 `{goal, continue, prompt, verdict}`，未通过时给出续跑提示 |
| `POST /threads/{id}/goal/pause` · `/resume` | 暂停（带原因）/ 继续（返回续跑提示） |
| `DELETE /threads/{id}/goal` | 清除目标 |

### 4.5 插件自带 MCP server 的协议要求

引擎用官方 MCP SDK 连接插件声明的 server：每条回包必须带 `"jsonrpc": "2.0"`，
通知（无 id）不得回包。四个自带 server（电脑 / 浏览器 / Minecraft / 星露谷）已按此修正——
此前它们在新 SDK 下全部连接失败，相关工具对所有智能体不可见。

## 五、桌面架构

- **workspace 状态层**（zustand）：项目、对话、团队、当前选中（对话 / 草稿 / 团队）、
  轮询与未读，以及目标续跑驱动。`useApp()` 保留为兼容门面，`sid` = 当前对话 ID（草稿与团队为 null）。
- legacy UI 已删除：`src/index.html` 是唯一入口（加载 `src/v2`），窗口固定无边框自绘标题栏；
  `src/lib` 只保留被复用的渲染模块（markdown / codediff / toolRender / toolLang）。
- 交互统一用 radix 原语（DropdownMenu / Popover / ContextMenu / Dialog），不再手写弹层定位与外部点击关闭。
- `flutter run --machine` 由主进程持有（`electron/lib/flutter.js`，按 daemon 协议：方括号帧、
  `event` 键、`app.restart` 带 `appId`、结束时杀进程树），渲染层 `pane/flutterRun.ts` 镜像状态。
