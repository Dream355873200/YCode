# YCode 体验与操作逻辑改造规划

> 2026-09-25。起因：模式 / 插件 / 角色卡 / 团队 / 流水线「构不成体系」，UI 各自为政。
> 本文先定**心智模型**（用户该怎么理解这些东西），再按**真实操作路径**审计断点，
> 最后给出分阶段改造。原则：关系靠操作体现，不靠文字说明。

## 一、心智模型：两根轴，不是五个名词

用户不需要理解五个平级概念。它们其实分属两根正交的轴：

```
            能力轴（Agent 会什么）              协作轴（几个 Agent 怎么配合）
            ──────────────────────              ────────────────────────────
  用户选择   模式  ────────────┐                 单人对话（默认）
                              │                  团队  = 常驻协作（有身份、有记忆）
  背后组成   插件 ← 工具集/技能/子代理/MCP        流水线 = 一次性分工（跑完即止）
                              │
  身份       角色卡 ── 只在团队里出现，= 模式 + 身份描述
```

- **模式**是唯一需要用户主动选的能力入口；插件/工具集是模式的「零件」，属于设置页里的
  高级配置，日常使用不该被迫接触。
- **角色卡不是新概念**：它 = 「一个模式（能力）」+「一段身份描述」。团队成员选模式即得能力，
  写一句身份即得角色——这就是之前说的「角色卡和 mode 重合」的消解方式，已在引擎落地
  （成员 `mode` 字段），但 UI 仍把「工具集勾选」放在首位，心智没对齐。
- **团队 vs 流水线**是同一根轴上的两种形态，却在右栏是两个平级孤立 tab，且流水线只能由
  agent 发起、用户无入口。

## 二、真实路径断点审计（按用户实际会走的路径）

| # | 路径 | 断点 | 严重度 |
|---|---|---|---|
| 1 | 群聊里 leader 需要用户拍板 | leader 调 confirm → 团队会话无前端连接 → **永久阻塞**，之后所有消息被插话进死 run，表现为「不回复」 | 致命（已修 9f32bf3）|
| 2 | 想停掉一个跑飞的成员 | 团队 run 不走 /chat，中断登记缺失，停止无效 | 高（已修）|
| 3 | 看群聊消息 | 每条 leader 通知写两遍（system→leader steer + 正文），长消息纯文本平铺刷屏 | 中（已修 c0524db：去重、Markdown、折叠）|
| 4 | 看成员在干什么 | 成员时间线是自制简陋渲染（工具只显示名字）| 中（已修：改主对话同款渲染）|
| 5 | 建团队 | 默认让人勾「工具集」这种底层零件；「继承模式」藏在第二个按钮 | 中（待改，阶段 1）|
| 6 | 编辑角色卡 | 群聊 → 点成员 → 进时间线 → 再点铅笔，三层 | 中（待改，阶段 1）|
| 7 | 自己发起一次流水线 | 没有入口，只能求 agent 调工具 | 中（待改，阶段 2）|
| 8 | 团队与流水线关系 | 右栏两个平级 tab，看不出同属「协作」| 低（待改，阶段 2）|
| 9 | 发现团队能力 | 新用户不知道团队存在，右栏「+」菜单里才有 | 低（待改，阶段 3）|
| 10 | 历史可见性 | 流水线历史已持久化，但团队群聊不分会话、无「上次在做什么」摘要 | 低（阶段 3）|

## 三、改造路线

### 阶段 1：团队操作扁平化（先做，改动集中在 TeamPanel）

1. **建团队 = 选模式 + 写身份**：成员卡片默认「能力：选择模式」下拉（默认继承当前项目模式），
   「按工具集精调」折叠为高级选项。模板预设同步改为按模式组合。
2. **成员 chip 直达编辑**：群聊头部成员 chip hover 出现铅笔，点击直接进编辑（砍掉进时间线那层）；
   时间线内保留编辑入口。
3. **群聊内快捷回复**：提问卡「回复」已做；审批卡与提问卡统一视觉（左色条 + 图标 + 主操作按钮）。
4. **空态引导**：团队列表空态给两个模板卡片（点即创建），不是一段说明文字。

### 阶段 2：右栏「协作」统一入口

1. 右栏「团队」「流水线」合并为一个「协作」tab，顶部分段控件切换两种形态；
   运行中的实体（跑着的流水线 / 有成员在忙的团队）在分段标签上显示活动点。
2. **流水线用户直创**：「新建流水线」表单——节点卡片列表（名称 / 指令 / 能力模式 / 上游），
   依赖通过「上游」多选建立，右侧实时预览 DAG；提交即调同一 `create_pipeline` 执行链。
3. 主对话里 agent 发起的流水线/团队分派，工具卡提供「在协作面板打开」直达。

### 阶段 3：可发现性与连续性

1. 新建项目 / 空会话时，在对话空态提供「组建团队」「编排流水线」两个入口卡片（与现有
   模式选择同级），而非只藏在右栏「+」。
2. 团队群聊按日分隔，重开时顶部显示「上次：leader 在等你确认 X」一行摘要（取最后一条
   未回复提问/审批）。
3. 设置页插件/工具集/子代理/MCP 归入「高级」分组折叠，日常只露出「模式」。

## 四、视觉一致性约束（全阶段适用）

- 图标只用 lucide；禁止 emoji 与字符图标（已清扫 710b526）。
- 状态语言统一：运行 = brand 色 + Loader 旋转；完成 = success + Check；失败 = destructive +
  X/CircleAlert；待定 = neutral 描边圆点。流水线节点、工具卡、任务面板、成员 chip 共用这套。
- 卡片层级：surface（容器）→ card（条目）→ 左侧 3px 状态色条（需要状态时）。
- 所有「只读回看」视图（节点轨迹 / 子代理 / 成员时间线）复用主对话 RowView 渲染，不再自制。
