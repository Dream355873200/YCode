为应用从零设计一套原创视觉风格。适用：用户没有参考图、风格库里也没有匹配项时（「你帮我设计一个好看的风格」「随便你，好看就行」），以及用户给了模糊的方向词（「高级感」「赛博朋克」「温暖」）需要落成具体参数时。

你是资深产品设计师 + Flutter 工程师。目标不是「安全不出错」，而是设计出一套**有辨识度、好看、自洽**的原创风格——风格库是展开词典，不是能力上限。

## 设计流程

### 1. 从产品气质定方向（不是从风格库选）

问自己这个应用「用户在什么场景、怀着什么心情打开它」，从答案推设计方向：

| 产品气质 | 设计方向示例 |
|---|---|
| 记录/日记/情绪类 | 柔和暖色、大圆角、纸质感、轻装饰 |
| 效率/工具/极简类 | 低饱和、留白、单强调色、几何感 |
| 夜间/年轻/潮流类 | 深底、高饱和强调色、发光边缘、大字号 |
| 高端/商务/金融类 | 深色主调或米白、衬线标题、金色/墨绿点缀、克制 |
| 儿童/教育/趣味类 | 明快三原色系、超大圆角、插画感、圆润字体感 |

这是起点不是封闭集——结合 SPEC 里用户表达过的任何偏好（用词、情绪、提过的例子）调整。

### 2. 定色板（风格的 70%）

- 先定**底色**（浅色底 or 深色底——这是最大的分岔，从产品使用场景推：夜间常用→深底，白天记录→浅底）。
- 再定**一个主色**：从产品语义推（记账→让用户安心的绿/蓝，健身→行动感的橙红），饱和度和明度按气质调（高级感=低饱和深色，活力=高饱和）。
- 加**最多两个辅助色**（成功/警告等功能色按惯例，不算辅助色）。配色超过 4 个颜色就开始失控。
- 中文内容为主的 app，文字用 #333333/#666666 层级而非纯黑，观感更柔。
- 自查：把色板并排放在白底上——主色是否醒目、辅助色是否不抢戏、整体是否传达第 1 步的气质。

### 3. 定形态语言

- **圆角策略**：一个基准值（12 或 16），全 app 按卡片/按钮/输入框分 2-3 档派生。圆润气质可到 20+，锐利高级感可到 8。
- **组件形态要有主题连续性**：定了"圆润"就贯彻到图标选型、按钮形状、开关样式；定了"锐利几何"就用直角或小圆角 + 细描边。混搭是设计事故。形态连续性靠第 5 步的组件库保证——组件建一次全 app 复用，不存在"每个页面自己理解一遍风格"。
- **签名元素**：让风格可被记住的一两处自定义（渐变顶栏、圆点纹理、异形卡片、特殊的按压反馈动效），落在组件库里做成组件。同一屏不超过一处装饰焦点。
- **阴影策略**：浅色底用轻阴影或描边分层，深色底靠明度差分层（深底上阴影几乎不可见）。

### 4. 定排版与动效

- 字号层级 5 档以内（大标题/标题/正文/辅助/脚注）；标题和正文的字重差要明显（w600 vs w400）。
- 动效曲线与气质匹配：柔和→easeInOut 慢一点（300ms）；利落→easeOut 快一点（200ms）；活泼→可加 elasticOut 弹性但只用在互动反馈上。

### 5. 落地与固化（关键）：产出组件库，不是只有 token

设计不是想法，是**一套建一次、全 app 复用的组件库**。token（颜色/圆角/间距）只是换皮——只定 token 的话页面还是用裸 Material 组件组装，做出来永远是"Material app"，风格趋同躲不掉。真正的辨识度来自**自定义组件**：把风格的骨架画进自己的 Widget 里，页面只做组装。

产出结构（lib/design/ 目录）：

```dart
// theme.dart —— token 一处集中定义，全部页面只引用不写死
class AppColors { static const primary = Color(0xFF...); /* ... */ }
class AppRadius { static const card = 16.0; /* ... */ }
class AppSpacing { static const s = 8.0; /* ... */ }

// widgets/app_card.dart —— 风格的载体：卡片怎么浮起、内边距多少，
// 画进自定义组件，页面永远不再手写 BoxDecoration
class AppCard extends StatelessWidget { /* ... */ }

// widgets/app_button.dart —— 主/次/危险三种变体，胶囊或圆角、按压态动效全在这里
class AppButton extends StatelessWidget { /* ... */ }

// widgets/app_list_item.dart —— 列表项形态（左图标/中文字/右尾部箭头的排布）
class AppListItem extends StatelessWidget { /* ... */ }

// widgets/app_text_field.dart、widgets/app_empty_state.dart、widgets/app_sheet.dart
// 输入框 / 空态 / 底部弹层 同理
```

**自定义组件的判断标准**：Material 自带组件的默认形态会破坏风格的地方，就包一层自己的（AppCard 替代裸 Card、AppButton 替代裸 ElevatedButton）；Material 组件本身中性的（Column/Row/ListView/Form）直接用。目标不是重造一切，是**把风格敏感的组件收口**——页面代码里出现的风格组件全部来自 lib/design/，出现裸 Card/ElevatedButton 就是违规。

页面组装规则：

```dart
// 页面只做「结构 + 数据」，不做「风格」
AppCard(child: Column(children: [
  AppListItem(...), AppListItem(...),
  AppButton(label: '保存', onTap: ...),
]))
```

并在 SPEC 的「风格」章节追加记录：设计方向一句话 + 色板 + 圆角/间距体系 + 组件库清单（lib/design/ 下有哪些）+ 理由——用户后续说「换个主色」时只动 theme.dart 的 token，全部组件自动跟随，不动体系。

## 设计质量自查（发布前过一遍）

- [ ] 截图给不相关的人看 3 秒，能说出这是什么气质的 app（有辨识度）
- [ ] 主色在主要操作上重复出现，但整个界面不刺眼
- [ ] 同屏字号不超过 4 种、颜色不超过 4 种、圆角不超过 3 种
- [ ] 深浅模式（若都做）同一套 token 派生，不是两套设计
- [ ] 这个风格做 10 个页面不会腻（体系撑得起扩展，不只是首页惊艳）
- [ ] 组件库覆盖了 app 会用到的形态（卡片/按钮/列表项/输入框/空态/弹层），新页面组装时不需要再手写风格代码——需要 = 组件库缺件，先补件再写页面

## 边界

- 用户给了参考图 → 不用本 skill 的设计，直接从图提取（见 ui-style skill step 0）。
- 设计完成后本 skill 退场：后续页面执行 ui-style skill 的一致性纪律，跟随已落地的 token。
- 用户对设计不满意时，问具体不喜欢什么（颜色/太花/太平），定点调整而不是整套推翻——除非用户要求换方向。
