为本项目创建或修改界面时，确定并遵循统一的视觉语言。适用：任何页面/组件的搭建——风格一致性是用户感知「专业感」的最大来源。

你是资深 Flutter 工程师兼 UI 实现者。核心纪律只有一条：**先定风格，再写界面；风格定了就全程跟随**。

## 开工前必做：风格决策（按优先级，先命中先用）

0. **用户给了参考图**（截图/设计稿/喜欢的 app 界面）→ **以图片为唯一真源提取风格**：用视觉能力逐项读出图片里的实际参数——底色、主色与强调色、圆角大小、间距密度、字号层级、组件形态（按钮/卡片/输入框长什么样）、图片占的比重。提取结果落成 theme.dart 的 token 常量，后续页面全程引用。风格库文件此时只作参考词汇（判断提取出的参数属于哪种气质），**不得反向套用库里的值覆盖图片里看到的**——图片里主色是墨绿就用墨绿，哪怕它整体像 apple-clean（库里写的是蓝）。
1. **用户文字描述了风格**（「苹果风」「简洁点」「商务感」）→ 文字通常只有几个词，缺的参数**自己按描述气质补齐**：先读风格库定义文件（`knowledge/styles/` 下最接近的一种，如 apple-clean.md / card-stream.md）作为骨架，描述里没提到的 token 直接沿用库定义，描述里提到或暗示的（「不要红色」）按用户的话调整。补齐后同样落 theme.dart 常量。
2. **项目里已有页面？** → 读 1-2 个现有页面，提取实际用到的色板/圆角/间距/组件形态，**跟随现状**——哪怕不完美，一致性优先于先进性。此后的新页面都以既有页面为准。（除非 SPEC 风格章节记录过用户变更，以 SPEC 为准。）
3. **无参考图、库里也无匹配，或用户放权给你设计**（「你看着办」「帮我设计个好看的」「高级感」这类方向词）→ **调用 design skill 从零原创**：按产品气质定方向 → 设计色板/形态/排版/动效 → 落 theme.dart token 并记进 SPEC。不要退回平庸的 Material 3 默认——设计是你的能力，风格库只是词典。
4. **以上都没命中**（完全零输入的老项目）→ 默认 Material 3（useMaterial3: true）+ 中性主色 + 常量间距体系兜底。

优先级总结：**参考图 > 用户显式文字要求 > SPEC 风格章节 > 项目现状 > 原创/默认设计**。风格库的角色是「文字描述的展开词典」——把三个字补成完整参数；用户给了图，图就是参数本身；用户放权，就拿出设计能力。

风格定义文件的意图：把「苹果风」「卡片流」这类三个字的描述展开成可执行参数。读它时注意它的**反模式清单**——违反反模式比漏掉正面规格更破坏风格。

## 一致性硬规则（无论什么风格）

- **颜色**：全部经 Theme/常量引用。同一个"主色"在两个文件里出现两次硬编码值 = 缺陷。
- **组件库优先**：项目有 `lib/design/` 组件库（design skill 的产出）时，页面**只组装不自绘风格**——卡片用 AppCard、按钮用 AppButton、列表项用 AppListItem，页面代码里出现裸 Card/ElevatedButton/手写 BoxDecoration = 违规。缺新形态时先去组件库补件，再回页面组装。
- **间距**：用一套尺度（4/8/12/16/24/32），不要出现 13、17 这种随意值。
- **圆角**：全 app 统一 2-3 档，混搭圆角是"业余感"最大来源。
- **字号**：只用 Theme 的 title/body/label 体系 + 风格定义的字号表，不逐处写死。
- **组件复用**：同形态的东西（列表项/对话框/空态/表单字段）第二次出现就抽成共享 Widget，第三次出现必须抽。
- **深色模式**：颜色全走 Theme（不写死 Color(0xFF...)）时自然支持；SPEC 没要求就不专门做，但选色时别把"只适合浅色"的对比度写死。

## 高频坑

1. 无 Scaffold 的页面缺 AppBar/背景色 → 白屏或异常。
2. Column 溢出（黄黑条纹）：列表项内容不定长时用 Expanded/Flexible 或 SingleChildScrollView，不要固定高度。
3. 文本溢出不处理：长文案必须 maxLines + overflow: TextOverflow.ellipsis。
4. SafeArea 缺失：沉浸式状态下内容顶进状态栏。
5. 响应式用 MediaQuery.of(context).size 判断断点，写死像素宽度适配不了平板。

## 验收

- 新页面与既有页面（或所选风格定义）并排对照：色板/圆角/间距/组件形态一致，像同一个 app
- 真机冒烟截图自检一遍（不是只看代码）
