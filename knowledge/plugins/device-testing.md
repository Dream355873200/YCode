# 插件：设备测试（device-testing）

让 AI 在真实 Android 设备/模拟器上操作和验证 Flutter 应用——不是纸上
谈兵跑 analyze 就宣布完成，而是 tap 进去、看到状态变化、留下证据。
工具链分六层，按成本升序使用：能用便宜层证明的，不要往下走。

## 工具清单

| 工具 | 层级 | 输入 | 输出 / 断言 |
|---|---|---|---|
| `ui_tree` | L1 语义树 | 无 | 屏幕语义树（uiautomator dump）——弹窗/权限框/原生控件都在；节选节点 bounds 供 tap 定位 |
| `tap` | L2 交互 | x, y | 点击（坐标来自 ui_tree 节点 bounds 或截图目测） |
| `swipe` | L2 交互 | x1,y1,x2,y2 | 滚动列表 / 切页 / 下拉刷新 |
| `type` | L2 交互 | text | 向焦点输入框输入（先 tap 点中输入框） |
| `back` | L2 交互 | 无 | 返回键：关弹窗 / 上一页 |
| `wait_for` | L3 断言 | text（timeout 可选，默认 10s） | 轮询语义树等文本出现——**目标必须是操作产生的可见状态变化**（成功提示/列表变化），「页面还在」不算断言 |
| `screenshot` | L4 视觉 | 无 | 截图路径；带画面稳定检测（动画/滚动中自动等 0.3-3s） |
| `screen_diff` | L4 视觉 | before, after；或 action=save/check + tag | 降采样像素对比（零模型成本）：diff≈0 = 画面无变化；基线模式见下 |
| `logcat` | L5 日志 | 过滤参数 | 设备日志——行为断言：有没有 crash、关键日志有没有打出 |
| `net` | L6 网络 | action | 前后端联调：请求到达了吗、返回了什么 |
| `vision_ask` | L4+ 视觉 | 问题 + 截图 | 多模态目视判断（白屏/错位/布局异常），比人便宜、比像素比对聪明 |
| `test_report` | 交付 | 各层证据 | 固化测试报告文件；对话里只报结论摘要 |

## 使用模型（分层成本策略）

```
L1 语义树（零像素，最便宜）→ L2 交互 → L3 wait_for 文本断言
  → L4 截图/diff（像素）→ L5 logcat → L6 网络 → vision_ask（最贵，最后）
```

- **内环**（每完成一个功能）：analyze 零 issue 后只测核心路径 1-2 条
  （tap + wait_for 确认到达）；带副作用的操作断言可见状态变化。
- **外环**（收尾/SPEC 里程碑）：全路径 + 截图对比 + 联调，调
  `test_report` 固化；内环已验证过的条目直接引用证据，不重跑。
- **设备忙**：同一设备被别的会话占用时工具会拒绝并排队提醒——
  不要重试轰炸，等系统通知。

## 状态与数据

| 落盘 | 位置 | 复用方式 |
|---|---|---|
| 截图基线 | `<项目>/.yume/baselines/<tag>.png` | `screen_diff` action=save 存基线、action=check 拿当前屏与基线对比（截图+diff 一步完成）——回归验证「页面长得跟上次一样」 |
| 测试报告 | 项目 `.yume/` 报告目录（test_report 工具管理） | 工作台「报告」页签展示；压缩后重注入会把最新报告带回上下文 |

基线 tag 用页面名（home / detail / settings）。UI 有意变更后要重新
save 基线，否则回归永远 diff 非零。

## 扩展指引（加一个新设备工具）

1. **归属层级**：新工具放进上面六层模型里的哪层？纯读取（不影响
   设备状态）打只读副作用分级；tap/swipe 这类操作保持独占。
2. **命名**：小写下划线（`pull_file` / `grant_permission`），与现有
   工具风格一致；一个工具一个动作，组合逻辑交给模型按层级编排。
3. **实现位置**：`engine/internal/tools/device.go`，遵循现有模式——
   adb 命令封装 + 输出截断 + 设备忙检查 + testLogAppend 记时间线。
4. **文档同步**：本文件的工具清单加一行；`knowledge/skills/testing.md`
   的 allowed-tools frontmatter 与分层说明按需更新。
5. **回归**：在真实设备上验证工具本身（成功/失败/设备离线三态），
   再跑一次「生成 → analyze → 设备测试」闭环。
